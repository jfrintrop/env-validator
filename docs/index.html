Fail fast on bad environment variables

Declare the variables your PHP or Laravel app needs — types, allowed values, per-environment rules — using the validation rules you already know. Catch mistakes at boot or in CI, not three screens into a user flow.

Real output from the package — pick a scenario.

Schema
EnvValidator::make([
    'APP_ENV'   => 'required|in:local,staging,production',
    'APP_DEBUG' => 'required|boolean',
    'DB_PORT'   => 'required|integer|between:1,65535',
])->validate();
Environment: APP_ENV=prod, DB_PORT=abc
Environment validation failed with 2 problems:
  - The APP_ENV environment variable must be one of: local, staging, production.
  - The DB_PORT environment variable must be an integer.
Schema
EnvValidator::make([
    'APP_ENV'    => 'required',
    'APP_DEBUG'  => 'required|boolean',
    'STRIPE_KEY' => 'nullable|string',
])->whenEnvironment('production', [
    'APP_DEBUG'  => 'required|declined',
    'STRIPE_KEY' => 'required|starts_with:sk_live_',
])->validate();
Environment: APP_ENV=production, APP_DEBUG=true
Environment validation failed with 2 problems:
  - The APP_DEBUG environment variable must be disabled (false, 0, no, off).
  - The STRIPE_KEY environment variable is required but missing.

Why use it

Rules you know

Laravel validation syntax under the hood — no new DSL.

Env-aware

Handles true/false/null/empty and quoted values like env() does.

Per-environment rules

Stricter requirements for production, relaxed for local.

CI friendly

Proper exit codes for env:validate and env:example --check.

Typed values

Opt in to int, float and bool results.

Works standalone

The core needs no framework — any PHP 8.1+ project.
